# Failed to verify GitHub Artifact Attestations

`aqua >= v2.67.0`

You may face the error when you install a package providing [GitHub Artifact Attestations](/docs/reference/security/github-artifact-attestations).

e.g.

```console
$ aqua i
WRN execute gh attestation verify args="attestation verify ... -R suzuki-shunsuke/mkghtag" credential=gh error="exit status 1" failure=rate_limit ...
ERR aqua failed doc="https://aquaproj.github.io/docs/reference/codes/008" error="verify a package with gh attestation: verify GitHub Artifact Attestations" program=aqua
```

## What does this error mean?

aqua verifies GitHub Artifact Attestations by running [GitHub CLI](https://cli.github.com/) (`gh attestation verify`) internally.
This error means the verification failed, so aqua didn't install the package.

aqua tries the following GitHub access tokens in order until the verification succeeds.

1. GitHub CLI's own credential (`GH_TOKEN`, `GITHUB_TOKEN`, or `gh auth login`)
1. `AQUA_GITHUB_TOKEN`
1. The access token managed by [the keyring](/docs/reference/security/keyring)
1. The access token managed by [ghtkn](/docs/reference/security/ghtkn)
1. No access token

If GitHub CLI doesn't have its own credential, it's tried last instead of first.

Before aqua v2.67.0, aqua skipped the verification if GitHub CLI failed because of the authentication.
aqua doesn't skip it anymore, because skipping the verification would install packages without verifying them.

The output of GitHub CLI and the warning `execute gh attestation verify` show the cause.
The attribute `failure` of the warning shows how aqua classified the failure.

## How to solve the error

### The verification failed (`failure=verification`)

GitHub CLI outputs `verifying with issuer` or `expected ... to be ..., got ...`.

The package may be tampered with, or the registry settings may be wrong.
Please don't disable the verification to avoid the error.
Please check the package and [the registry settings](/docs/reference/security/github-artifact-attestations#registry-settings).

### No attestation is found (`failure=no_attestation`)

GitHub CLI outputs `no attestations found`.

The package doesn't provide GitHub Artifact Attestations, or the registry settings may be wrong.
Please check [the registry settings](/docs/reference/security/github-artifact-attestations#registry-settings).

### Rate limit, authentication, or permission errors (`failure=rate_limit`, `failure=invalid_token`, `failure=auth`, `failure=permission`)

GitHub CLI outputs `API rate limit exceeded`, `HTTP 401: Bad credentials`, `gh auth login`, or `HTTP 403`.

Without an access token, GitHub CLI calls GitHub API without authentication, so the verification may fail because of the rate limit of unauthenticated requests (60 requests per hour per IP address).
Please pass a valid GitHub access token by one of the following ways.

- The environment variable `GITHUB_TOKEN` or `AQUA_GITHUB_TOKEN`
- [The keyring](/docs/reference/security/keyring)
- [ghtkn](/docs/reference/security/ghtkn)

On GitHub Actions, you can pass the access token easily.

```yaml
- run: aqua i
  env:
    GITHUB_TOKEN: ${{ github.token }}
```

If the access token is blocked by SAML SSO, please authorize the access token for the organization.

### Not Found (`failure=not_found`)

GitHub CLI outputs `HTTP 404: Not Found`.

If the package is a private repository, please pass a GitHub access token which can access the repository, and set [private: true](/docs/reference/registry-config/private) in the registry.
aqua tries other access tokens only if the package is private.

### No GitHub access token is available

aqua outputs `no GitHub access token is available for gh attestation verify`.
All access tokens have been disabled because they were invalid or hit the rate limit.
Please pass a valid GitHub access token as described above.

## Disable the verification

If you can't solve the error, you can disable the verification by the environment variable.
We don't recommend it for security.

```sh
export AQUA_DISABLE_GITHUB_ARTIFACT_ATTESTATION=true
```
